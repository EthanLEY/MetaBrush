# MetaBrush 技术文档

> EXIF 元数据批量处理工具 —— 技术设计、实现细节与工程实践
>
> 版本：1.0 · 适用代码：`D:\Tools\MetaBrush` 工作区

---

## 1. 项目概述

### 1.1 目标

MetaBrush 是一个 Windows 桌面工具，用于给照片**批量写入相机 EXIF 元数据**，同时**清洗原图中的 AI 溯源信息**（prompt / workflow / AICG 等）。用户选择图片后，程序会：

1. 按预设模板（佳能R5 / 索尼A7M4 / 尼康Z8）填充机身、镜头、光圈、快门、ISO、焦距等 EXIF 字段；
2. 将拍摄时间（DateTimeOriginal / DateTimeDigitized）设为处理时刻；
3. 随机生成中国范围内（纬度 18–54°N，经度 73–135°E）的 GPS 坐标，每张图独立随机；
4. **删除原图中的 AI 元数据**：PNG 只保留 IHDR 基础信息（宽高/位深/色彩类型/压缩/滤波/隔行），JPEG 删除 XMP 与 COM 段；
5. 直接覆盖原图，且**保证操作系统记录的创建/修改/访问时间绝对不变**。

### 1.2 技术栈与环境

| 项 | 值 |
| --- | --- |
| 语言 | Python 3.10（兼容 3.10–3.12，构建验证于 3.12） |
| GUI | CustomTkinter（锁定 `>=5.2,<6.0`，原因见 §9.4） |

## 2. 系统架构

### 2.1 模块职责

```
┌─────────────── main.py（GUI，主线程）───────────────┐
│  文件选择/去重/列表渲染    进度条    彩色日志          │
│  ── 点击「开始处理」──►  后台工作线程（非守护）         │
└──────────────┬──────────────────────────────────────┘
               │ 队列（queue.Queue）+ after 轮询回主线程
               ▼
┌─────────── processor.process_file（每张图独立）───────┐
│  1. 扩展名校验（.jpg/.jpeg/.png）                      │
│  2. 读取尺寸（Pillow，失败不阻塞）                     │
│  3. 构建 EXIF（exif_builder）→ piexif.dump            │
│  4. JPEG：jpeg_io.insert_exif（严格解析+清洗+替换/插入）│
│     PNG ：png_io.insert_exif（严格解析+清洗+插入 eXIf） │
│  5. 原子写入（同目录临时文件 + os.replace）            │
│  6. SetFileTime 恢复创建/修改/访问时间                 │
└──────────────────────────────────────────────────────┘
```

- **主线程**只做 UI 与队列轮询；**工作线程**逐张处理文件，通过 `queue.Queue` 回传
  日志/进度事件，主线程用 `after(80, poll)` 消费。工作线程设为**非守护**：即使窗口被
  关闭，也会把当前批次全部处理完，避免中途被杀导致文件半截。
- 单张失败**不中断批次**：捕获异常 → 红色日志 → 继续下一张（需求 8）。

### 2.2 数据流（单张图片）

```
原图字节 ─► 严格解析（校验签名/标记/长度/完整性）
        ─► 清洗（PNG 删附属块 / JPEG 删 XMP+COM）
        ─► 写入新 EXIF（替换旧 EXIF / 插入新 APP1 或 eXIf）
        ─► 组装完整字节流
        ─► 原子写回原路径
        ─► 恢复三个时间戳
```

## 3. 核心模块详解

### 3.1 `metabrush/presets.py` — 预设模板

三套机身的 EXIF 字段模板，统一为有理数/整数：

| 键 | 类型 | 说明 |
| --- | --- | --- |
| make / model | str | 机身厂商/型号（如 `Canon EOS R5`、`SONY` + `ILCE-7M4`、`NIKON CORPORATION` + `NIKON Z 8`） |
| lens_make / lens_model | str | 镜头厂商/型号（如 `RF24-105mm F4 L IS USM`） |
| f_number | (n, d) | 光圈 F 值有理数（如 `(28, 10)` = F2.8） |
| shutter | (n, d) | 曝光时间有理数秒（如 `(1, 125)`） |
| iso | int | 感光度 |
| focal_length | (n, d) | 焦距 mm |
| exposure_program / metering_mode | int | EXIF 枚举（3=光圈优先，5=评价测光） |

### 3.2 `metabrush/exif_builder.py` — EXIF 构建

生成 piexif 可序列化的字典，包含：

- **0th IFD**：Make、Model、Orientation、DateTime、X/YResolution、ResolutionUnit；
- **Exif IFD**：ExposureTime、FNumber、ExposureProgram、ISOSpeedRatings、
  DateTimeOriginal、DateTimeDigitized、ShutterSpeedValue、ApertureValue、
  FocalLength、MeteringMode、WhiteBalance、ColorSpace、ExifVersion、
  FlashpixVersion、ComponentsConfiguration、LensMake、LensModel、
  PixelXDimension/YDimension（来自实际图片尺寸）；
- **GPS IFD**：GPSVersionID、GPSLatitudeRef/Latitude、GPSLongitudeRef/Longitude、
  GPSAltitudeRef/Altitude、GPSTimeStamp、GPSDateStamp。

关键换算（APEX 标准）：

```
ApertureValue (Av) = 2·log2(FNumber)
ShutterSpeedValue (Tv) = -log2(曝光时间)
```

GPS 度分秒表示：

```
度/分/秒 = [(d,1), (m,1), (round(s·100), 100)]
```

**注意**：新写入的 EXIF **不含 Software 字段**（需求：禁止在元数据中添加软件信息）。

时间：`DateTimeOriginal` / `DateTimeDigitized`（及 0th `DateTime`）取**处理时刻**的本地
时间，格式 `YYYY:MM:DD HH:MM:SS`；GPS 时间戳取处理时刻的 UTC 时间。

### 3.3 `metabrush/jpeg_io.py` — JPEG 段级读写

#### 段结构

JPEG = SOI(`FF D8`) + 若干段 + SOS(`FF DA`) + 扫描数据 + EOI(`FF D9`)。

每个带长度段：`FF <marker> <len_hi> <len_lo> <payload>`，**len 包含自身的 2 字节**。

#### 严格解析（`_iter_segments` 生成器）

- 逐个产出 `(marker, segment_bytes, next_pos)`，遇到 SOS 或 EOI 停止，扫描数据原样保留；
- **标记校验**：只接受合法标记（`0x01` TEM 与 `0xC0–0xFE`），非法标记（如 `0x32`）抛错；
- **长度校验**：`len < 2` 或越界即抛错；段间截断即抛错；
- 解析到文件尾仍未命中 SOS/EOI 视为结构不完整，抛错。

设计原则：**宁可跳过，绝不写坏**——只要结构无法完整合法解析，就抛 `ValueError`，
由上层跳过该文件且不改动原文件。

#### 写入（`insert_exif`）

- 已存在 APP1(Exif)（`payload` 以 `Exif\0\0` 开头）→ **原位替换**为新的 EXIF 段；
- 无 EXIF → 在 SOS 前**插入**新的 APP1(Exif)；
- **元数据清洗**：删除 XMP（APP1，payload 以
  `http://ns.adobe.com/xap/1.0/\0` 或 `http://ns.adobe.com/xmp/extension/\0` 开头）
  与 COM（`FF FE`）段——AI 信息（prompt/workflow）常见载体；
- 其它段（APP0/JFIF、APP2/ICC/MPF、APP13 等）与扫描数据**逐字节保留**，不做重压缩。

### 3.4 `metabrush/png_io.py` — PNG 块级读写

#### 块结构

PNG = 8 字节签名 + 若干块。每个块：`len(4B BE) + type(4B) + data(len) + crc(4B)`，
CRC = `crc32(type + data)`。

#### eXIf 规范要点

- eXIf 块数据 = **不含** JPEG APP1 `Exif\0\0` 头与长度字段的原始 TIFF 数据
  （依据 PNG 规范；Pillow/ExifTool 同约定）；
- **IHDR 必须是第一个块**（历史 bug：eXIf 曾插到 IHDR 之前，被严格校验工具判为损坏）；
- eXIf 必须位于 IHDR 与 IEND 之间、且不在 IDAT 之间 → 本实现固定插在 IHDR 之后。

#### 元数据清洗（AI 溯源防护）

只保留：

| 块 | 原因 |
| --- | --- |
| IHDR | 必须第一；宽高/位深/色彩类型/压缩/滤波/隔行 |
| eXIf | 本程序新增的 EXIF |
| PLTE | 调色板图片必需，删除则无法解码 |
| tRNS | 透明信息，删除会改变外观 |
| IDAT / IEND | 图像数据 |
| 未知**关键块**（首字母大写，如 CgBI） | 影响解码，不能删 |

**全部删除**：`tEXt`、`zTXt`、`iTXt`（prompt/workflow/parameters/Description/AICG
等文本载体）、旧 `eXIf`、`tIME`、`gAMA`、`pHYs`、`sRGB`、`cHRM`、`iCCP`、`bKGD`、
`sBIT` 等所有附属块，以及 IEND 之后的尾部字节。

#### 完整性校验

- 块长度越界（`c_end > n`）→ 抛错；
- 未遇到 IEND（文件被截断）→ 抛错。

### 3.5 `metabrush/processor.py` — 处理管线与数据安全

#### 原子写入（防损坏核心）

```
写同目录临时文件（mkstemp）→ write + flush + fsync → os.replace(临时, 原文件)
```

- 原文件任何时刻都只处于「完整旧内容」或「完整新内容」两种状态；
- 进程被杀、断电、磁盘满、杀软拦截等中断**都不会**产生半截/空文件；
- 替换失败时清理临时文件，原文件保持原样。

#### 时间戳恢复（需求 5：创建/修改时间绝对不变）

- `os.replace` 会产生新文件（创建时间变化），因此处理后必须恢复：
- **Windows**：`SetFileTime` 同时恢复创建/修改/访问时间。纳秒 → FILETIME 换算：
  ```
  FILETIME = ns//100 + 11644473600·10^7   （Unix 纪元 → 1601 纪元，单位 100ns）
  ```
  注意：直接用 `os.utime` 无法恢复创建时间，且 FILETIME 换算必须加纪元偏移
  （历史 bug：漏加偏移导致时间整体差 11644473600 秒，被单测当场捕获）。
- **其它平台**：`os.utime`（尽力而为）。

#### 失败恢复

- 结构解析失败（`ValueError`）→ 返回 `(False, 原因)`，**文件未被触碰**；
- 写入阶段异常 → 清理临时文件后向上抛出，原文件保持完整；
- 时间戳恢复失败不影响文件内容（只影响时间戳）。

### 3.6 `main.py` — GUI 与调度

- **布局**：顶部已选数量徽标；中部预设下拉框 + 「添加文件」/「清空列表」+
  文件列表（双击移除）；底部进度条 + 状态 + 「开始处理」+ 彩色日志。
- **线程模型**：见 §2.1；处理中禁用相关按钮；`WM_DELETE_WINDOW` 处理中关闭需确认。
- **彩色日志**：`CTkTextbox` tag（成功绿 / 错误红 / 系统蓝 / 提示黄 / 信息灰）。

## 4. 格式与规范细节

### 4.1 JPEG 段长度语义（易错点）

段的 `len` 字段**包含长度字段自身的 2 字节**。解析时「读取 marker 字节后，再前进
`len` 字节」；若误写成 `len + 2` 会每段错位 2 字节，导致输出损坏
（历史 bug，已修复并有逐字节比对测试）。

### 4.2 PNG eXIf 与 IHDR 顺序（易错点）

- PNG 规范要求 IHDR 必须是第一个块；任何块（含 eXIf）出现在 IHDR 之前即非法，
  严格校验工具会直接判为损坏（历史 bug，已修复并有块顺序回归测试）。
- eXIf 数据不带 `Exif\0\0` 头（piexif.dump 输出需 `[6:]` 去掉）。

### 4.3 EXIF 结构

- TIFF 头 + IFD 链：0th（含 ExifTag/GpsTag 指针）→ Exif IFD → GPS IFD；
- 有理数以 `(numerator, denominator)` 存储；ASCII 字段以字节串存储；
- piexif.dump 输出以 `Exif\0\0` 开头（JPEG APP1 需要），PNG 侧需剥离。

## 5. 元数据清洗策略（AI 溯源防护）

| 载体 | 处理 |
| --- | --- |
| PNG `tEXt`/`zTXt`/`iTXt`（prompt/workflow/parameters/Description/AICG） | 整块删除 |
| PNG 旧 `eXIf` / `tIME` / `gAMA` / `pHYs` 等附属块 | 整块删除 |
| PNG PLTE / tRNS / 未知关键块 | 保留（渲染必需） |
| JPEG XMP（APP1，xap 命名空间） | 段删除 |
| JPEG COM（`FF FE`） | 段删除 |
| JPEG 旧 EXIF（含 UserComment 等可能携带 prompt） | 整体替换为新 EXIF |
| 新 EXIF 的 Software | **不写入** |

## 6. 异常与容错

- 每张图独立 `try/except`，失败记红色日志后继续；
- 结构异常 → `(False, 原因)` 或异常 → 跳过，**原文件不改动**；
- 未预期异常向上抛出，由 GUI 记录。

## 8. 构建与发布

### 8.1 一键打包（`build.bat` / `build.ps1`）

流程：

1. 创建 `.venv` 并安装依赖（customtkinter / Pillow / piexif / pyinstaller）；
2. 运行单元测试，未通过则中止；
3. `PyInstaller --onefile --windowed --name MetaBrush --collect-all customtkinter main.py`

4. 用 `WScript.Shell` 在桌面创建/覆盖快捷方式「MetaBrush」（指向 EXE）。


## 9. 已知限制与注意事项

1. **PNG 清洗会删除 gAMA/pHYs 等附属块**：图片像素不变，多数查看器按 sRGB 默认渲染；
   这是「只保留 IHDR 基础信息」需求的有意取舍。
2. **Windows WIC 不通过属性面板展示 PNG eXIf 元数据**（JPEG 正常）；图片本身解码正常，
   不影响打开。
3. **随机 GPS 仅覆盖中国范围**（纬度 18–54°N，经度 73–135°E），每张独立随机。
4. **piexif 的 IFD next-pointer 存在已知小瑕疵**（ExifIFD/GPS IFD 的 next 指针非 0，
   Exiv2 会告警但可正常读取；PIL/WIC 均正常）。如需零告警输出需自行重排 TIFF，当前
   版本不处理。
5. **文件被其它程序独占锁定时**：读取或替换失败会跳过该文件并标红，不会损坏。
6. **网盘/云同步目录**：建议处理前暂停同步，避免同步客户端与写入竞争。
